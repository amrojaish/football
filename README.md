## ⚠️ دروس تقنية حاسمة — لا تُنسَ

اكتُشفت بالتجربة وكلّفت وقتاً طويلاً. **قراءتها تمنع تكرار الكارثة.**

### 1. حد الطلبات بالدقيقة (أخطر اكتشاف)
الخطة المجانية ~10 طلبات/دقيقة (**غير معلن في التوثيق**). تجاوزه يُرجع
**رد HTTP 200 بمصفوفة فاضية بدون أي رسالة خطأ** — يبدو تماماً كأنه
"لا توجد بيانات لهذه المباراة".

هذا جعلنا نظن أن الـAPI لا يملك أحداثاً للدوريات العربية (تغطية 35%)،
وكدنا **نلغي فكرة المشروع كلها**. الحقيقة: كل الأحداث موجودة.

- خطة مجانية: `DELAY = 7.0` ثانية
- خطة Pro: `DELAY = 1.0` (مُختبر ويعمل)

### 2. الفشل الصامت — أخطر نمط برمجي
```python
return r.json().get("response", [])   # يبتلع كل الأخطاء
```
**أي دالة تجلب بيانات يجب أن تفحص الأخطاء وترجعها، لا أن تخفيها.**
الصيغة الصحيحة: `return (نجح؟, البيانات, سبب_الفشل)`

**إشارة تحذير مهمة:** الحصة استُهلكت 26 بدل 52 المتوقعة. فسّرتها
كخبر جيد. كانت في الحقيقة **إنذاراً** — الطلبات المرفوضة لا تُحتسب.

### 3. `Missed Penalty` ليست هدفاً
الـAPI يصنّفها `type = "Goal"`. رونالدو ظهر بهدفين وأحدهما ركلة ضائعة.
```python
if e.get("detail") == "Missed Penalty": continue
```

### 4. أهداف ملغاة بمباريات 0-0
تظهر بجدول الأحداث ولا تدخل بالنتيجة (تسلل/VAR)، وغالباً **بلا اسم لاعب**.
يعالجها `fix_goals.py`.

### 5. الفلاتر الناقصة (تكررت مرتين)
كل استعلام يحتاج `league_code AND season`. نقص أحدهما يخلط البيانات
**بصمت**. أول مرة كان الدوري، الثانية الموسم.

### 6. `INNER JOIN` يحذف بصمت
الأندية غير الموجودة بجدول `teams` **تختفي من النتائج بلا تحذير**.
ظهر جدول ترتيب بـ**8 فرق بدل 10** لهذا السبب — الفريقان الصاعدان
(البقعة، سما السرحان) لم يكونا بالجدول.

### 7. الشبكة غير موثوقة
انقطاعة واحدة أسقطت سحب 374 مباراة عند المباراة السادسة.
الحل: `try/except` + إعادة محاولة بتأخير متزايد + **تخطي** الفاشل
بدل الانهيار. (اختُبر فعلياً ونجح)

### 8. الدمج لا الاستبدال
أي سكربت يلمس ملفاً فيه شغل يدوي **يجب أن يدمج**. الاستبدال يمحو
ساعات عمل بصمت. (`update_teams.py`, `export_players.py`)
⚠️ `fetch_teams.py` القديم كان يستبدل — **حُذف لهذا السبب**.

### 9. مسار الداتا — التعديل لا يصل وحده
```
teams_arabic.csv → [sync_teams.py] → football.db → [make_site3.py] → index.html
```
أي تعديل على الـCSV يحتاج `sync_teams.py` بعده، ثم `make_site3.py`.

**وبعد أي سحب جديد:**
```
fetch_matches2.py → apply_exclusions.py → apply_corrections.py → make_site3.py
```
تخطّي هذه الخطوات يُرجع الأخطاء المصححة والمباريات المحذوفة يدوياً.

### 16. ترتيب المتساويين لا يُحسب بفارق الأهداف
الدوريات الثلاثة ترتّب المتساويين بالنقاط عبر **المواجهات المباشرة**
أولاً، لا بفارق الأهداف الكلي.

مثال مؤكد (السعودي 2025-26):
```
الفتح   37 نقطة · فارق -14 · المركز 11
الخليج  37 نقطة · فارق -8  · المركز 12
```
الفارق الأفضل لا يعني مركزاً أعلى.

**لا يُكتب بـSQL بشكل نظيف** — يحتاج: تجميع المتساويين، حساب مواجهاتهم،
ترتيبهم داخل المجموعة، ثم إعادة دمجهم. لذلك `tiebreak.py` وحدة منفصلة.

**القواعد الرسمية:**

| الدوري | الترتيب | الثقة |
|---|---|---|
| الأردني | نقاط ← نقاط المواجهات ← فارق المواجهات ← أهداف المواجهات ← فارق كلي ← أهداف كلية | [مؤكد] — المادة 13، لائحة بطولات الاتحاد الأردني |
| السعودي | نقاط ← نقاط المواجهات ← فارق المواجهات ← أهداف المواجهات ← فارق كلي ← أهداف كلية | [مؤكد] — تحقق خارجي |
| العراقي | نقاط ← نقاط المواجهات ← فارق المواجهات ← **فارق كلي** ← أهداف كلية | [مرجح] — IPFL عبر ويكيبيديا |

⚠️ **فرق تقني:** العراقي ينتقل لفارق الأهداف الكلي بعد فارق المواجهات
مباشرة — بدون خطوة "أهداف المواجهات" الموجودة بالأردني والسعودي.

⚠️ **السعودي يفرّق بين الترتيب أثناء الموسم والترتيب النهائي:** حتى
الجولة قبل الأخيرة يُرتَّب بفارق الأهداف الكلي، وبالنهاية بالمواجهات.
كودنا يطبّق قاعدة النهاية (الموسم مكتمل 34/34).

**المفعّل حالياً: السعودي والعراقي.** (العراقي فُعِّل 17 أغسطس بعد
اكتمال 2023 و2024 و2025 — 38 مباراة لكل نادٍ في الثلاثة.)

**دليل الأثر — العراقي 2023:**
```
النجف   67 نقطة · فارق +17 · المركز 4
زاخو    67 نقطة · فارق +17 · المركز 5
```
متطابقان في النقاط **وفارق الأهداف**، فالحسم بالمواجهات وحدها.
وقبل التفعيل كان `compare_standings.py` يُظهر «زاخو عندنا 4 ≠ عندهم 5»،
وبعده **اختفى الفرق** — أي أن H2H قرّبنا من الترتيب الرسمي.

⚠️ **`H2H_ENABLED` مفتاح لكل دوري لا لكل موسم.** تفعيل دوري يطبّقه
على كل مواسمه بأثر رجعي. فحص الأثر قبل التفعيل إجباري.

**الأردني لا يزال معطّلاً:** نظام 3 مراحل — عدد المواجهات بين الفرق
قد يختلف، ولا يوجد حالياً أي تعادل نقاط بالجدول (لا أثر عملي).

### 23. المباريات القادمة تكسر حسابات الجدول


للفرق التي لم تلعب بعد، و`tiebreak.py` يحاول `-None`.

1. **حساب الجدول:** أضف `AND home_goals IS NOT NULL` لكل استعلام

### 26. `player_id` يجعل الترجمة تُكتب مرة واحدة
المزوّد يعطي لكل لاعب معرّفاً ثابتاً عبر كل المباريات والمواسم
والأندية. تخزينه (لا الاسم فقط) يعني أن ترجمة الاسم مرة واحدة
تنطبق على كل ظهور له — حتى لو انتقل لنادٍ آخر.

⚠️ **جدول `goals` لا يخزّن `player_id`** — يخزّن `player_en` نصاً

هشّة، بينما `lineup_players` و`player_stats` تربط بالمعرّف.

**عند إصلاح ذلك:** أعد سحب الأهداف مع `player_id`، أو اربط
النصوص بالمعرّفات عبر `player_stats` مرة واحدة.

### 27. الجداول التفصيلية تُفصَل ولا تُدمَج
خمسة جداول منفصلة بدل واحد ضخم:

```
goals          → أحداث الأهداف (له منطق تنظيف خاص)
events         → بطاقات وتبديلات (لا يدخل حسابات الهدافين)
match_stats    → صف لكل فريق بالمباراة (أرقام مُجمَّعة)
lineups        → صف لكل فريق (الخطة والمدرب)
lineup_players → صف لكل لاعب (18-20 لكل فريق)
player_stats   → صف لكل لاعب (~30 عموداً)
```

**المنطق:** لكل جدول حبيبية مختلفة (مباراة / فريق / لاعب).
دمج الخطة مع اللاعبين كان سيكرّرها 18 مرة. ودمج البطاقات مع
الأهداف كان سيعقّد كل استعلام هدافين في المشروع.

**والأهم:** سكربتات السحب الأربعة (`fetch_events`، `fetch_stats`،
`fetch_lineups`، `fetch_player_stats`) **لا تلمس `matches` ولا
`goals`** — فالتصحيحات اليدوية بأمان تام، ولا تحتاج إعادة
تشغيل سلسلة المعالجة بعدها.

### 39. المتصفح يحفظ الصفحة بدل تنزيل الملف

ملف تحقق Google (`google42cb06cb72108c7f.html`) محتواه الصحيح **سطر
واحد**. عند فتحه بدل تنزيله، حفظه Chrome كصفحة كاملة:

```html
<!-- saved from url=... -->
<html><head><meta ...></head><body>google-site-verification: ...</body></html>
```

فشل التحقق برسالة "wrong content"، والتحذير المضلّل
`LF will be replaced by CRLF` دفع التشخيص في اتجاه خاطئ تماماً.

**العلاج:** تصنيع الملف بالأمر مباشرة، لا الاعتماد على المتصفح:

```powershell
Set-Content -Path <file> -Value "<السطر>" -NoNewline -Encoding ascii
```

⚠️ وتنزيله مرتين ينتج `... (1).html` — نسخة ثانية منشورة على
   الموقع. احذفها، واستثنِ ملف التحقق من الخريطة عبر `SKIP_FILES`.

⚠️ **لا تحذف ملف التحقق أبداً** — Google يفحصه دورياً.

### أعمدة `teams_arabic.csv`
```
league_code | league_ar | team_id | name_en | name_en_official
name_ar | short_name_ar | city | logo | logo_local | logo_note
```
- `name_en` — **اسم المزوّد**، يُحتفظ به كمرجع ولا يُعرض
- `name_en_official` — ⭐ الاسم الإنجليزي الرسمي، **هذا المعروض**
- `short_name_ar` — الاسم العربي المختصر، **هذا المعروض**
- `logo_local` — مسار شعار محلي يتجاوز شعار الـAPI الخاطئ
- `logo_note` — توثيق سبب التصحيح (لم يعد يُعرض في الموقع)

### أعمدة `club_names_review.csv`
```
team_id | league | current_api_name | official_english | confidence | note
```
- `confidence` = مؤكد / مرجح / تخميني
- **[تخميني] لا يُطبَّق** — يُترك فارغاً ويرتد لاسم المزوّد

### أعمدة `match_corrections.csv`
```
match_id | league_code | season | correct_home | correct_away | note | source
```
- `note` — سبب التصحيح (مثال: "هدف د.13 ملغي — النتيجة الرسمية 0-0")
- `source` — من أين جاءت النتيجة الصحيحة (سجل شفاف)
- إذا كانت النتيجة الصحيحة 0-0، السكربت يحذف أهداف المباراة تلقائياً

### أعمدة `excluded_matches.csv`
```
match_id | league_code | season | reason | source
```
- للمباريات التي وضعها الـAPI تحت `league_id` خاطئ

### أعمدة `team_merges.csv`
```
old_id | new_id | league_code | note | source
```
- لما يملك الـAPI معرّفين لنفس النادي، فيظهر مرتين بأرقام ناقصة

### أعمدة `manual_matches.csv`
```
match_id | league_code | season | date | home_name | away_name
home_goals | away_goals | note | source
```
- **المعرّفات تبدأ من 9000001** لتمييزها عن معرّفات الـAPI
- الأسماء تُطابَق مع `short_name_ar` — لا معرّفات، أسهل بالكتابة اليدوية
- بعض التواريخ تقديرية وموثّقة بذلك في `note`
- هذه المباريات بلا أحداث في `goals` — صحيح، فهي لم تُلعب

### أعمدة `players_ar.csv`
```
priority | goals | league | team_ar | player_en | player_ar
```
- `priority` = A (قوائم الدوريات) · B (صفحات الأندية) · C (مخزّن)
- **الفئة A = 68 اسماً فقط** تغطي كل ما يظهر بالصفحة الرئيسية
- إعادة التصدير **لا تمحو** الترجمات الموجودة

### أعمدة `player_merges.csv`

```
old_name | keep_name | confidence | note
```
- لتوحيد `C. Ronaldo` مع `Cristiano Ronaldo`
- ⚠️ **لا يُستخدَم لتشابه اللقب فقط** — راجع درس 28

### جداول `football.db`
```sql
teams   (team_id, league_code, name_en, name_ar,
         short_name_ar, city, logo)
matches (match_id, league_code, season, date,
         home_id, away_id, home_goals, away_goals, status)
goals   (id, match_id, team_id, minute,
         player_en, player_ar, detail)
events  (id, match_id, team_id, minute, type, detail,
         player_en, player_ar, assist_en)

match_stats     (match_id, team_id, possession, shots_total,
                 shots_on, corners, fouls, saves, passes_total,
                 passes_pct, xg, ...)

lineups         (match_id, team_id, formation, coach_en, coach_ar)

lineup_players  (match_id, team_id, player_id, player_en,
                 player_ar, number, pos, grid, starter)

player_stats    (match_id, team_id, player_id, player_en,
                 player_ar, minutes, rating, shots_total, goals,
                 assists, passes_total, passes_key, tackles,
                 duels_won, dribbles_ok, ...)

api_standings   (league_code, season, team_id, rank, played,
                 wins, draws, losses, goals_for, goals_against,
                 points, form, description, fetched_at)
```
⚠️ `api_standings` **مرجع للمقارنة لا مصدر للحقيقة** — درس 29.
⚠️ عمود `player_ar` **فارغ بالكامل** في الجدولين — هذا عمل مؤجل.

**جدول `events`:** منفصل عن `goals` عمداً — `goals` له منطق تنظيف خاص
(`fix_goals.py`) وخلطه بالبطاقات كان سيعقّد كل استعلامات الهدافين.
- `type` = `Card` / `subst` / `Var` / `none`
- `detail` = `Yellow Card` / `Red Card` / `Substitution 1` ...
- `assist_en` = اللاعب الخارج في التبديل
- `type='none'` = سجل فارغ يمنع إعادة سحب مباراة بلا أحداث

   نتيجة خاطئة متسقة مع نفسها. (درس 13)
