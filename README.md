### 1. الفشل الصامت — أخطر نمط في المشروع كله

تكرّر بستة أشكال مختلفة، وكلها تُنتج **نتيجة معقولة المظهر
وخاطئة المضمون** بلا رسالة خطأ واحدة:

| الشكل | المثال |
|---|---|
| `INNER JOIN` يحذف صفوفاً | مباريات بلا نادٍ مطابق تختفي من الجدول |
| متغيّر مبني وغير مُدرَج | يُحسب ثم لا يُستعمل — والصفحة تُبنى ناقصة |
| نسختان من دالة بملف واحد | الثانية تطغى على الأولى بصمت |
| سكربت سحب مع مباريات قادمة | يعيد صفراً ويُبلغ نجاحاً |
| سجل مراجعة مكتمل ≠ مطبَّق | الملف صحيح والديتابيس لم يتغيّر |
| كلاس CSS بحرف واحد | يطابق عنصراً آخر — المتصفح لا يشتكي |
| قائمة دوريات مقفلة يدوياً بالكود | `lineup_view.py` كان يعرض التشكيلات للسعودي وحده (`LINEUP_LEAGUES={"SAU"}`) — تشكيلات المصري/الإماراتي مخزَّنة كاملة بالديتابيس ولم تظهر على الموقع شهوراً، صفر رسالة (4 سبتمبر) |

**القاعدة:** بعد كل عملية، **تحقّق من الأثر لا من انعدام الخطأ.**
عدّ السجلات، قارن رقماً متوقَّعاً، افتح الصفحة. رسالة النجاح
تعني "اكتمل" لا "صحّ".

### 4. تغطية المزوّد تنقسم لطبقتين — لا لدوريات

الدوريين، **تحقّق أولاً أنه ليس هذا القيد** قبل البحث عن عيب.

### 9. مصائد الملفات والترميز على ويندوز

⚠️ **`Move-Item -Force` يستبدل بصمت.** مرتان كاد ملف سليم يُمحى
   (الـREADME استُبدل بملف 5,972 بايت من مشروع آخر). **كل نقل
   يتبعه فحص حجم قبل أي تشغيل أو كوميت:**
```powershell
Get-ChildItem <file> | Format-Table Name, Length
```
   وللملفات متكرّرة الأسماء، نزّلها **باسم مميّز** ثم أعد التسمية.

⚠️ **نهايات الأسطر المختلطة تكسر كل تعديل نصي لاحق** — 94 سطر
   LF داخل ملف CRLF جعل كل `str.replace` يفشل **بصمت**. الكشف:
```python
raw.count(b'\n') - raw.count(b'\r\n')   # يجب أن يساوي صفراً
```
   وحين يفشل `assert txt.count(old)==1` على نص تراه بعينك،
   **الترميز أو نهايات الأسطر هي السبب لا الصياغة.**

⚠️ **`Get-Content` يعرض العربي مشوّهاً حتى لو الملف سليم.** لا
   تحكم على الترميز من شاشة التيرمنال — استعمل `Format-Hex`:
   `D8`/`D9` = عربي سليم · `C3 98` = تالف · `EF BB BF` = BOM.

⚠️ **النسخ من المتصفح يجلب نصاً زائداً** — ملف YAML بدأ بـ
   `Live · YML` فرفضه المحلّل كلياً. **انقل الملف (`Move-Item`)
   ولا تنسخ محتواه عبر محرر.**

⚠️ **الملفات القديمة تكذب** — قبل الاعتماد على أي لقطة CSV
   كمرجع حالة، افحص تطابقها مع الديتابيس. لقطة قديمة كانت
   ستعتبر 569 ترجمة معطوبة "منجَزة".

⚠️ **`--help` غير مدعوم** — السكربتات لا تحلّل الوسائط، فأي
   وسيط مجهول يُتجاهَل ويعمل السكربت بوضعه الافتراضي.
   `python fetch_events.py --help` **شغّل سحباً فعلياً**
   واستهلك ~100 طلب. اقرأ رأس الملف بدلاً منه.

⚠️ **أي سكربت يكتب ملفاً يفشل إن كان مفتوحاً بـExcel.**

### 16. الخطأ الصاخب الذي ليس فشلاً

`update_all.py` أبلغ عن **15 خطوة فاشلة** بأخطاء حمراء صريحة:

وبايثون يعطي الأنبوب **ترميز النظام** (`cp1252` على ويندوز) لا

⚠️ **`encoding="utf-8"` في `subprocess.run` لا يكفي** — يحكم
   القراءة عندنا لا الكتابة عندهم. الحل تمرير البيئة:
```python
env = dict(os.environ, PYTHONUTF8="1", PYTHONIOENCODING="utf-8")
subprocess.run(cmd, capture_output=True, text=True,
               encoding="utf-8", env=env)
```

**وكيف فُرِز الحقيقي من الزائف:** برقم السطر في كل خطأ. الخطأ
عند `print` في نهاية الدالة = العمل تمّ؛ الخطأ عند سطر 137 قبل
حلقة السحب = المهمة لم تُنفَّذ. **رقم السطر يفرّق بين الاثنين
في ثوانٍ.**

**القاعدة:** درس 1 يحذّر من الفشل الصامت. هذا نقيضه —
**نجاح صاخب يتنكّر في هيئة فشل**. الاثنان يُعالَجان بالمبدأ
نفسه: تحقّق من **الأثر** لا من الرسالة.

### 23. `rebase` عالق ومتناقض — و`--abort` آمن بشرط

`push_all.py` رفض الرفع: "هناك rebase غير مكتمل". والفحص أعطى
حالة متناقضة:
```
git status              → "all conflicts fixed: run --continue"
git diff --diff-filter=U → (فارغ)
git ls-files -u          → (فارغ)
git rebase --continue    → "You must edit all merge conflicts"
```
ثلاثة أوامر تقول "لا تعارضات" وأمر رابع يرفض.

**المخرج: `git rebase --abort`** — يلغي محاولة الدمج ولا يمسّ
الملفات على القرص.

⚠️ **بشرط واحد لا يُتجاوَز:** تحقّق أن الملفات سليمة **قبل**
   الإلغاء لا بعده:
```powershell
python state.py    # 3,207 مترجَم · IRQ 2022: 380
```
   لو كانت الأرقام صحيحة، فالعمل بالقرص وليس بالـrebase —
   والإلغاء بلا خسارة. لو كانت خاطئة، فالإلغاء يفقد الحل ويجب
   الاسترجاع من كوميت أولاً (درس 8).

⚠️ **وبعد `--abort`، أعد التشغيل بـ`push_all.py` لا يدوياً** —
   هو يحلّ تعارض `football.db` تلقائياً بالاتجاه الصحيح، وقد
   نجح من أول محاولة بعد الإلغاء.

`live.yml` مكتوب `*/5` (كل 5 دقائق) و`update-site.yml` مكتوب
`*/30`. **التنفيذ الفعلي المرصود: مرة كل ~4.5 ساعة، ومرة واحدة
بفجوة سبع ساعات.** الملفان صحيحان والتشغيلات كلها خضراء — الخنق
من GitHub نفسه على المستودعات المجانية وقت الضغط.

**الأثر:** `live.json` كان يُقرأ كل 60 ثانية من صفحة عمرها سبع
ساعات. الواجهة سليمة والاختناق كان في من يكتب الملف.

**ما لا ينفع:** تكثيف الجدولة — الطلب الأكثر يُخنق أكثر.

**الحل المطبَّق (3 سبتمبر):** إخراج النتائج المباشرة من GitHub
Actions كلياً إلى **Cloudflare Worker** بجدولة خاصة به. راجع
قسم "النتائج المباشرة" في هيكل الملفات.

⚠️ **القاعدة العامة:** أي شيء وقته حسّاس لا يُبنى على
   `schedule:` في GitHub Actions. المهام غير الحسّاسة (توليد
   الصفحات، الخرائط) تحتمل التأخير ولا تحتاج نقلاً.

## مبادئ متفق عليها

1. **التحقق قبل البناء** — لا يُكتب كود قبل إثبات توفر الداتا
2. **الأصول اليدوية هي الميزة** — الأسماء والشعارات والتصحيحات لا تُنسخ بسهولة
3. **فصل البيانات عن المنطق** — الكود يعرف *كيف*، والداتا تقول *ماذا*
4. **الديتابيس المحلية أولاً** — العمل على الداتا لا يستهلك الحصة
5. **توثيق التصحيحات لا محوها** — `logo_note` و`note`/`source` سجل شفاف
6. **أي نتيجة مخالفة للتوقع تستحق تفسيراً** — حتى لو بدت إيجابية.
   الشذوذ الصغير المُهمَل أخفى أكبر باگ بالمشروع.
7. **صلّح المصدر لا النتيجة** — التنظيف وحده علاج للعَرَض؛
   يجب تعديل مسار الإدخال أيضاً.

   في ملف CSV يُعاد تطبيقه. التعديل المباشر يضيع مع أول سحب جديد.
9. **المقارنة الخارجية إجبارية قبل النشر** — لا يوجد فحص داخلي يكشف
   نتيجة خاطئة متسقة مع نفسها. (درس 3)
10. **لا يُكتب منطق مبني على قاعدة غير مؤكدة** — قواعد الترتيب تختلف
    بين الدوريات. التعطيل الصريح أفضل من التطبيق التخميني. (درس 10)

    والعراقي بلا بطاقات، ووفّرت 1500 طلب و25 دقيقة. (درس 4)

    يعرف الحقيقة. اترك له ما لا مصدر له فقط. (درس 3)

15. **لا تخمّن عموداً غير ظاهر في المصدر** — للمعادلة أكثر من حل،
    والقيمة المحسوبة من الداتا أوثق من المستنتجة. (درس 10)
